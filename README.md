# icfes-results-by-internet-access

This repository aims to establish a relation between ICFES results and internet access by Colombian municipalities, using open data from [datos.gov.co](https://datos.gov.co).

---

## Project structure
```
icfes-results-by-internet-access/
├── data.py                  
├── transform_clean.py      
├── requirements.txt
├── README.md
└── (HDFS: spark-master:9000 — bloques en spark-worker1/2)
    └── /data/
        ├── raw_json/
        │   ├── icfes/
        │   │   ├── part_0000.jsonl
        │   │   ├── part_0001.jsonl
        │   │   └── ...
        │   ├── internet/
        │   │   └── ...
        │   └── bachillerato/
        │       └── ...
        └── parquet/
            ├── icfes/
            ├── internet/
            └── bachillerato/
```

All data is stored in **HDFS** (`hdfs://spark-master:9000`), not on the local disk of the master node. The NameNode and WebHDFS API run on **spark-master** (this machine); block storage lives on the DataNodes **spark-worker1** and **spark-worker2**. Extraction uploads via WebHDFS (`http://spark-master:9870`); Spark reads/writes Parquet through the NameNode RPC endpoint.

- `/data/raw_json/` — `.jsonl` files downloaded from the Socrata API, paginated in batches of 5,000 records.
- `/data/parquet/` — Final version of the data in Parquet format, generated by Spark from the raw files. Raw JSON is automatically deleted after successful Parquet conversion.

## Usage

### Full run (extraction + Spark)

Downloads the raw data and generates the Parquet files in one step:
```bash
python3 data.py
```

With parallel download between datasets:
```bash
python3 data.py --parallel-downloads
```

### Extraction only

Downloads the `.jsonl` files to `data/raw_json/` without running Spark:
```bash
python3 data.py --extract-only
```
### Sample mode (development)

Downloads only the first N records per dataset, without running Spark. Useful for testing the pipeline locally without access to the cluster or the full dataset:
```bash
python3 data.py --sample 5000
```
Can be used together with `--extract-only`:
```bash
python3 data.py --extract-only --sample 5000
```

Can be combined with `--parallel-downloads`:
```bash
python3 data.py --extract-only --sample 5000 --parallel-downloads
```

### Spark processing only

Converts files in HDFS `/data/raw_json/` to Parquet (requires extraction to have been run first):
```bash
python3 data.py --spark-only
```

## HDFS storage and automatic resume

### Architecture

`data.py` stores all data directly in HDFS through WebHDFS, avoiding local disk usage entirely:

| Component | Address | Purpose |
|---|---|---|
| HDFS NameNode | `hdfs://spark-master:9000` | Metadata only on master; Spark reads/writes Parquet |
| WebHDFS | `http://spark-master:9870` | `data.py` uploads JSONL during extraction |
| HDFS DataNodes | `spark-worker1`, `spark-worker2` | Block storage (no DataNode on master) |
| Spark Master | `spark://spark-master:7077` | Cluster mode for Spark jobs |

### Automatic resume on failure

If the download is interrupted (network error, API timeout, etc.), simply re-run the same command:

```bash
python3 data.py --extract-only --parallel-downloads
```

The script will:
1. Scan HDFS for existing `part_XXXX.jsonl` files in each dataset directory
2. Skip all batches that were already successfully written
3. Download only the remaining batches
4. Print a summary showing how many batches were reused vs. newly downloaded

This means **no data is re-downloaded** and the process continues exactly where it left off.

### Retry logic

Each API request includes automatic retry with exponential backoff:
- Up to **5 retries** per batch on `ConnectionError`, `Timeout`, or `ChunkedEncodingError`
- Wait times: 5s → 10s → 20s → 40s → 80s between retries
- HTTP-level retries (via `urllib3.Retry`) for status codes 429, 500, 502, 503, 504

## Notebooks

### 03_coleccion_descripcion_datos.ipynb

Covers CRISP-DM phase: data collection and description. Loads the three raw JSONL datasets from `data/raw_json/` into Apache Spark (local mode, 2 GB driver) and describes them in terms of schema, attribute meaning, record counts, and basic descriptive statistics.

Datasets loaded:

| Dataset | Socrata ID | Source | Description |
|---|---|---|---|
| ICFES Saber 11 | `kgxf-xxbe` | ICFES | Individual student results for the Saber 11 exam |
| Internet access by municipality | `n48w-gutb` | MinTIC | Fixed internet connections by municipality |
| Educational coverage | `nudc-7mev` | MEN | Educational indicators by municipality and year |

Key findings documented in the notebook:

- All ICFES columns are ingested as `string`. Score columns (`punt_matematicas`, `punt_ingles`) require numeric casting before analysis.
- The `no_de_accesos` column in the internet dataset is stored as a string and may contain special characters. Speed columns use a comma as the decimal separator, requiring cleanup before numeric operations.
- Column names in the educational coverage dataset contain encoding artifacts from accented characters (e.g. `a_o`, `deserci_n`, `aprobaci_n`). These will be normalized in the transformation phase.
- The three datasets can be joined on municipality code and year to build an integrated territorial analysis of connectivity and educational outcomes.

### 05_limpieza_transformacion.ipynb

Documents the cleaning and transformation pipeline implemented in `transform_clean.py`. The notebook serves as an executable entry point for the pipeline; all transformation logic resides in the script. Requires `data/parquet/` to have been generated first by `data.py`.

The pipeline covers: numeric casting and normalization of DANE municipality codes (`lpad` to 5 digits); filtering of ICFES records to `estu_estadoinvestigacion = PUBLICAR` and global scores within the 0-500 valid range; removal of negative internet access values; IQR-based outlier removal (1.5x IQR) on `punt_global` and `no_de_accesos`; mean imputation for `punt_ingles` and `cobertura_neta`; and aggregation of internet connections by municipality and year joined with educational coverage to produce the derived variable `accesos_por_habitante`.

Clean output is written to `data/parquet_clean/` with four subfolders: `icfes`, `internet`, `bachillerato`, and `municipio_internet_cobertura`.

## ML / XGBoost Spark (`ml_train.py`, `ml_algorithms.ipynb`)

Distributed regression using [SparkXGBRegressor](https://xgboost.readthedocs.io/en/latest/tutorials/spark_estimator.html): one model for each ICFES score (`punt_global`, `punt_matematicas`, `punt_ingles`, `punt_lectura_critica`, `punt_sociales_ciudadanas`, `punt_c_naturales`). The other `punt_*` columns are **not** used as features (prevents data leakage).

### Prerequisites

- Parquet ICFES en HDFS: `hdfs://spark-master:9000/data/parquet/icfes`
- Internet y bachillerato en el mismo prefijo (para construir el join municipal si aún no existe `parquet_clean`)
- **Java 11** recomendado para el driver y executors (`ml_train.py` fuerza Java 11 si está instalado; Java 21 falla con PyArrow en XGBoost Spark)
- Mismas dependencias Python que el venv del proyecto (`pip install -r requirements.txt`)

### Training

```bash
source venv/bin/activate

# Desarrollo (muestra)
python ml_train.py --sample 100000

# Un solo target
python ml_train.py --sample 100000 --target punt_global

# Producción en clúster (sin muestra)
export SPARK_MASTER_URL=spark://spark-master:7077
export XGB_NUM_WORKERS=2
python ml_train.py
```

Models are saved to `hdfs://spark-master:9000/data/models/xgb_{target}/` (`preprocess/` + `xgboost/`).

### Evaluation metrics (hold-out test 15%)

| Metric | Meaning |
|---|---|
| **RMSE** | Typical error in score points (penalizes large errors) |
| **MAE** | Mean absolute error in points |
| **R²** | Explained variance (compare models) |

### Notebook

`ml_algorithms.ipynb` — loads data, trains (pilot or all 6 targets with `ML_TRAIN_ALL=1`), displays the metrics table, performs inference on a new record, and plots prediction vs actual values.

### Environment variables

| Variable | Description | Default |
|---|---|---|
| `SPARK_MASTER_URL` | Spark cluster URL | local[*] |
| `XGB_NUM_WORKERS` | XGBoost Spark workers | 2 (cluster) / 1 (local) |
| `ML_SAMPLE_N` | Row sample in notebook | 50000 |
| `ML_TRAIN_ALL` | Train all 6 targets in notebook (`1`) | `0` (pilot `punt_global` only) |
| `ML_USE_SYSTEM_JAVA` | Do not force Java 11 | — |

## Socioeconomic Profiling & Feature Importance (`ml_profiling.py`)

This module uses PySpark's native ML capabilities to build student socioeconomic profiles and calculate the exact influence of internet access versus other territorial mediators.

### K-Means Clustering & The Elbow Method

Performs clustering (`KMeans`) on students based on categorical context variables (`fami_estratovivienda`, `fami_educacionmadre`, etc.) and continuous features (`accesos_por_habitante`, `punt_global`).
- **Pipeline:** Categorical features are encoded using `StringIndexer` and `OneHotEncoder`. Numeric features are imputed and scaled with `StandardScaler`. All are combined using a `VectorAssembler`.
- **Optimal K:** The algorithm iteratively calculates the Silhouette Score (`ClusteringEvaluator`) for `k=2` up to `k=max-k` to find the optimal number of profiles.
- **Evaluation:** Once the optimal K is found, the final model is trained and evaluated, displaying the final Silhouette Score and the distribution of students across the newly found socioeconomic profiles.

### Random Forest Feature Importance

To explicitly answer "to what extent internet access mediates ICFES scores," the module trains a `RandomForestRegressor` targeting the global score (`punt_global`).
- **Data Splitting:** Data is randomly split into 80% training and 20% testing sets.
- **Evaluation:** Evaluated on the test set using `RegressionEvaluator` to measure RMSE, MAE, and R-squared.
- **Insights:** The model outputs the exact Feature Importances of all socioeconomic and municipal variables. This quantifies whether household internet, computer access, or mother's education has a stronger predictive weight on the academic outcome.

### Usage

```bash
source venv/bin/activate

# Development (sample and max K of 8)
python ml_profiling.py --sample 50000 --max-k 8
```

| Option | Description | Default |
|---|---|---|
| `--sample N` | Row sample for quick development | 50000 |
| `--max-k N` | Maximum number of clusters to test for the Elbow Method | 8 |

The `ml_algorithms.ipynb` notebook also includes this profiling pipeline, providing a plot of the Silhouette Score vs. number of clusters (Elbow Method curve) and a bar chart visualizing the Feature Importance of the Random Forest model.
